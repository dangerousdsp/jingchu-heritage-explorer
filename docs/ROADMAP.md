# 后续工程恢复与改进

## 当前已经完成的网页改进

自适应布局、资料入口与来源、组合筛选、地区地图、收藏和云游路线、独立视频、阅读手记、小测解析和历史成绩、按需加载、错误反馈和本地启动。原始 Unity 构建保持原样。

## 恢复工程后优先修复

1. **物理配置。** FeiYi3D 场景序列化统计有 22,771 个 Rigidbody、30,531 个 MeshCollider；实测出现非凸网格与动态刚体不兼容错误。逐层检查静态建筑与装饰、鼓模型子物体，去掉不必要刚体并简化碰撞。不能简单给所有网格勾选 Convex。验收：启动和完整互动流程不再出现该错误，人物不穿地、模型不意外散落。
2. **按钮生命周期。** `ButtonVisibilityController` 的淡出逻辑调用 `Destroy(button)`，且多个按钮共用标记。改成面板 CanvasGroup 与可取消的单一动画。验收：连续三次靠近—离开—再靠近，按钮都可正常恢复。
3. **资源加载。** 先用构建报告定位模型拆分、纹理和重复资源。为展品与戏台分离资源加载；仅异步切场景不会自动缩小 data 包。用同一台电脑记录传输量、加载耗时与帧率，不把减少首屏请求误写成已优化模型性能。
4. **交互与 UI。** 统一视频控制器、准备/错误状态、返回目录逻辑和相机操作；把鼓的公共动作与鼠标、键盘、XR 输入分开。

## 不安装 Unity 时的恢复工作

优先分析 Windows `BackUpThisFolder` 中的 Managed DLL 与 PDB，而非先从 Wasm 逆向。可用 ILSpy 恢复可读业务代码，AssetRipper 分析场景与资源；输出到独立本地目录，记录恢复来源。先验证一个展品场景，再决定扩展恢复或建立新工程。本轮尚未交付可编译的恢复工程。

## 后续独立功能

地市边界与专题联动已在 0.3 实现；下一阶段可增加经核实的精确地点资料。账户、后台与云端进度在有实际需求后新增。真实 VR 需设备验证，现有 XR 插件文件与模板不能替代适配测试。

## 0.3 已实现与下一步

当前已实现地市 GeoJSON 导览、六个专题联动、收藏、线上云游路线、独立视频课堂、本地视频预览、十题挑战与个人历史成绩。此前规划中的地市导览已落地；精确地点与实地路线仍需要逐一核实的地点资料。

短期可继续补充经过核实的专题、视频说明和有效题目，加入可访问性检查与截图展示，并整理个人开发说明。这些工作不依赖 Unity。

旧程序内部仍需恢复工程：除戏台物理错误，本轮切换编钟时也观察到运行时卡顿，需记录目标场景、资源占用和触发过程再定位。不能仅靠网页超时提示修复 Wasm 主线程阻塞。真实头显、模型性能和内部字体/UI 改造需要可编辑工程与对应设备验证。

账户、论坛、云端视频上传和多用户排名属于需要后端的新阶段；先确定持续使用场景，再选择存储、内容管理和身份方案，避免将本地预览误写成云服务。

## 0.4 已落地的旅行功能

地区分布已升级为街道地图、核实目的地和实际路网规划；已有8个文化目的地，支持按站生成方向与导航。后续优先增加传承体验馆/工坊的经核实地址和公开入口、细化适合步行的单城行程，并逐步补齐剩余名录资料详解。公开大流量服务需选择稳定的地图与路由服务。

当前场馆坐标主要为公开OSM近似定位，不是全部门口坐标。黄鹤楼已通过停车场接驳解决本轮实测吸附到隧道的问题；其他目的地仍需现场和官方渠道确认入口。原Unity工程恢复、物理修复和真实VR验证仍按前述计划推进。
